PRD: Internship & Job Listing Portal

Type: Internship mini project (Full Stack) | Level: Beginner | Duration: 2 weeks | Version: 2 Source: Internship Mini Project Assignment PDF + product decisions confirmed by the author

1. Overview

A basic web platform where users can browse internship/job opportunities, search and filter them, view details, and submit applications. Admins log in to manage opportunities and view applications.

Purpose of the project (from the assignment): help the intern understand frontend, backend, database, and API integration.

2. Goals and Non-Goals

Goals

  • Users can view, search, filter, and open opportunities.
  • Users can apply to an opportunity and get a saved confirmation they can open again later.
  • Admins can log in, add, edit, delete opportunities and view applications.
  • Deliver all final submission items (see Section 10).
  • The project is evaluated overall (frontend, backend, database, integration), not on one part only.

Non-goals (post-project, not in this scope)

  • User authentication
  • Resume file upload
  • Email notification

3. Users

User What they do
Applicant (user) Browses opportunities and submits applications (no login)
Admin Logs in, manages opportunities, views applications

4. Suggested Tech Stack (as suggested in the assignment)

  • Frontend: React.js
  • Backend: Node.js + Express.js (REST APIs)
  • Database: MongoDB

5. Functional Requirements

5.1 User features

ID Requirement
U1 View the list of opportunities (all shown, newest first; no pagination)
U2 Search opportunities by title only
U3 Filter opportunities by domain (fixed dropdown)
U4 View opportunity details (including its Application Link)
U5 Submit an application through an in-app form
U6 See an application confirmation with a unique application ID/link
U7 Open the saved application again later using that ID/link

5.2 Admin features

ID Requirement
A0 Admin login (admin account stored in the database); admin features require login
A1 Add an opportunity
A2 Edit an opportunity
A3 Delete an opportunity
A4 View applications (one list of all applications, showing which opportunity each belongs to)

6. Data Requirements

6.1 Opportunity

Field Notes
Job/Internship Title Searched by U2
Company Name Not searched
Type Job or Internship (field only; filtering by type is not required)
Domain Fixed dropdown: Web Development, Data & AI, UI/UX Design, Marketing, Other
Location
Experience Simple text field
Description
Application Link Shown on the details page, alongside the in-app form

6.2 Application

Field Rule
Name Required
Phone number Required
Email Required
Resume link Optional (a URL, not a file upload)
Short message Optional
Application ID Unique, generated by the system
Opportunity Linked to the opportunity applied for
  • Duplicate applications (same email, same opportunity) are blocked.
  • Each application is saved, and shown again through its unique ID/link.

6.3 Admin account

  • Stored in the database; used for admin login (A0).

7. Core User Flows

Applicant: Opportunity list → search by title / filter by domain → details → application form → confirmation with unique ID/link → reopen later via the ID/link.

Admin: Login → opportunity list → add / edit / delete → view applications.

8. Timeline (from the assignment)

Week 1: Planning, frontend and backend setup

  • Understand requirements and plan the application flow
  • UI design and project structure
  • React setup; opportunity listing and details pages; search and filter UI
  • Node + Express setup; REST APIs; MongoDB models; DB connection; basic opportunity APIs

Week 2: Integration, features and finalization

  • Connect frontend with backend APIs
  • Opportunity CRUD; application submission; search and filtering; application confirmation
  • Test the complete app; fix bugs; improve UI/UX
  • README.md and documentation
  • Deploy (if applicable)
  • Screenshots and final presentation

Admin login is not in the PDF's weekly plan. It was added to scope by the author, so plan it into the Week 1/Week 2 work.

9. Constraints

11. Post-Project Backlog (deferred bonus features)

  1. User authentication
  2. Resume upload

12. Assumptions (defaults chosen, change if the mentor says otherwise)

  • Opportunity list shows everything at once, newest first.
  • The Application Link is displayed on the details page; the in-app form is the main way to apply.
  • Only Name, Phone, Email are required; no other validation rules were requested.
  • Admin sees one list of all applications.
